# S.V. Dross — maps & waypoints system

How the deck plans, hull conforming, waypoint guides, and side elevation are built,
and **exactly how to regenerate them after editing the ship.** Everything is data-driven
from one source of truth; the web pages render it live.

---

## Source of truth & data flow

```
setting/ship-layout.json   ──(generated mirror)──>   docs/assets/ship.js  ──(read live by)──>  docs/maps.html
setting/set-dressing.json  ──(routing inputs)────────────────────────────────────────────────  docs/profile.html
```

- **`setting/ship-layout.json`** — canonical spatial model. Hand-edit this (or the authoring
  tools below), never `ship.js`.
- **`docs/assets/ship.js`** — `window.DROSS_SHIP = {…}`; a **generated** mirror of the JSON.
  Regenerated by `conform-decks.mjs` and `route-waypoints.mjs`. **Never hand-edit.**
- **`docs/maps.html`** — top-down deck plans, rendered client-side from `ship.js`.
- **`docs/profile.html`** — orthographic side elevation (decks as layers), also from `ship.js`.
- **`setting/set-dressing.json`** — per-room `hug` side, `work_zones` (routing obstacles),
  floor `dressing`, and the OSHA `design_code` (clearances). Inputs to the waypoint router.

### Key fields in `ship-layout.json`

- `decks[]` — each has `id`, `level` (A=3 top … D=0 bottom), `grid:{w,h,unit_m}`, `rooms[]`,
  and geometry:
  - `hull` — **convex** top-down hull cross-section for this deck, in grid coords `[x,y]`
    (x=beam/starboard, y=fore→aft). Rooms are CLIPPED to this so perimeter walls follow the
    shell. **Must stay convex** (the room clip is Sutherland–Hodgman).
  - `hull_outline` — *optional* **concave** silhouette drawn as the shell stroke, used where
    the real outline isn't convex. **Deck A only**: the winged hammerhead + body silhouette.
    (Renderer draws `hull_outline || hull`.)
- `rooms[]` — `id`, `name`, `map_label`, `rect:{x,y,w,h}` (grid units), `doors[]`, `spoiler`,
  and optionally:
  - `poly` — explicit polygon `[[x,y]…]` drawn **as-is, unclipped**. Used for shapes that
    jut PAST the body and must not be hull-clipped — i.e. **the Bridge = the hammerhead**.
- `connectors[]` — vertical links across decks (ladderway, crawlspace, infection-spine).
- `entities[]` — props/NPCs with `deck`, `room`, `pos:{x,y}`, `kind` (drives color), `spoiler`.
- `wayfinding` — `routes[]` (each `id`, `deck`, `role` solid=primary/dashed=secondary, `path[]`,
  `entry`/`exit`/`rooms` from the router) and **`deck_colors`** (the per-deck guide colors).
- `exterior` — the structured 3D exterior design (hammerhead, hull_body, aft_bulb, maw).

---

## Design rules (don't regress these)

1. **Decks taper A→D.** D widest/longest (swollen aft cargo/reclamation bulb) → A narrowest
   (command). Each deck footprint = the hull cross-section at its height.
2. **The Bridge IS the hammerhead** (Deck A): a wide thin crossbar of sensor/grapple wing pods
   jutting PAST the hull on both sides, raked cockpit nub forward, necking into the habitation
   spine. Implemented as `bridge.poly` (unclipped) + Deck A's concave `hull_outline`. Deck A's
   `hull` stays the convex *body* (clips the habitation rooms).
3. **The maw is EXTERNAL** — an articulated salvage boom off the aft-starboard, NOT a walkable
   deck room. Deck D's aft interior is the **Reclamation Bay (rear cargo door)**.
4. **Waypoint guides are per-deck hi-vis colors, distinct from the room/entity UX palette**
   (amber `#f2b441` / teal `#4fd1c5` / purple `#a78bfa` / coral `#ff7a6b`). Current guide
   colors: deck-a `#b6ff00` lime, deck-b `#ff36c4` magenta, deck-c `#00c2ff` azure, deck-d
   `#ffffff` white (in `wayfinding.deck_colors`).
5. **Guides are OSHA/Dead-Space leading-lines**: ORTHOGONAL (segments parallel to walls, 90°
   turns), hugging one side at a visible offset — never diagonal shortcuts, never on the wall.
   Clearances live in `set-dressing.json` `design_code` (aisle 0.71 m, **wall_offset 0.6 m**,
   equipment 0.9 m). The router is hull-aware so lines never enter the hull-clipped margin.
6. **Plot rooms must survive any re-lay** (see `adventure/last-call.md`): stasis-bay + gladys-core
   (Sc0), mess-hall→scrubber-corridor `blocked_by mr-munch` (Sc1), crawlspace + scrubber-control
   + faulty maintenance-airlock (Sc2), cargo-hold nest + salvaged-pod + cargo-airlock (Sc3),
   infection-spine connector. Stacking must stay A→D for the descent.

## The tools (`setting/*.mjs`)

| Tool | What it does | Idempotent? |
|---|---|---|
| `conform-decks.mjs` | Sets each `deck.hull` (+ Deck A `hull_outline`, `bridge.poly`), grows perimeter `rect`s out to the shell, sets `wayfinding.deck_colors`, relabels the maw room. Regenerates `ship.js`. | **Yes** (absolute values). Safe to re-run while tuning hulls/colors. |
| `conform-dressing.mjs` | **One-shot.** Remaps every `set-dressing` work_zone + floor-dressing item AND every entity `pos` from its OLD room frame into the NEW conformed rect (proportional). Guarded by `set-dressing.json` `_conformed_v2`. | **No** (relative). Runs once; delete `_conformed_v2` to re-run after another room move. |
| `route-waypoints.mjs` | Computes clearance-aware **orthogonal** `wayfinding.routes[].path` (A* with hug-one-side, inset by `wall_offset`, hull-aware, equipment obstacles). Regenerates `ship.js`. Route specs (rooms/entry/exit) are the `SPECS` table at the bottom — edit there. | Yes. Re-run after ANY room move. |
| `render-decks.mjs` | **Visual check harness** (not part of the site). Writes `cairn-review/decks/deck-*-{warden,player}.svg` + `deck-profile.svg`, replicating `maps.html`/`profile.html` geometry incl. the identical hull-clip. Rasterize with cairosvg to eyeball. | Yes. |

The hull-clip function `clipRoomToHull()` is duplicated **verbatim** in `docs/maps.html` and
`setting/render-decks.mjs` — keep them identical (the harness is the regression check).

## REGENERATE (run from the repo root, in order)

After editing rooms/hulls (in `ship-layout.json` directly, or in `conform-decks.mjs`):

```bash
node setting/conform-decks.mjs          # hulls, rects, hammerhead, deck colors  -> ship-layout.json + ship.js
node setting/conform-dressing.mjs        # ONLY if rooms moved: remap dressing+entities (one-shot; rm _conformed_v2 to redo)
CAIRN_DIR=. node setting/route-waypoints.mjs   # clearance-aware orthogonal waypoint paths -> ship-layout.json + ship.js
node setting/render-decks.mjs            # visual check -> cairn-review/decks/*.svg
# rasterize a deck to eyeball it:
uv run --no-project --with cairosvg python -c "import cairosvg; cairosvg.svg2png(url='../cairn-review/decks/deck-a-warden.svg', write_to='/tmp/a.png', output_width=900)"
```

`ship.js` is regenerated by both `conform-decks.mjs` and `route-waypoints.mjs` (whichever runs
last), so after the sequence above it mirrors `ship-layout.json`. `maps.html` and `profile.html`
read it live — just reload.

**Common edits**
- *Move/resize a room:* edit its `rect` (in `ship-layout.json` or the `RECT` map in
  `conform-decks.mjs`) → run the FULL sequence (room moves invalidate dressing + paths; reset
  `_conformed_v2` if you need the dressing remap to re-run).
- *Reshape a deck hull:* edit `HULL`/`OUTLINE`/`POLY` in `conform-decks.mjs` → full sequence.
  Keep `deck.hull` convex.
- *Change a guide color:* edit `wayfinding.deck_colors` (set in `conform-decks.mjs`) → run
  `conform-decks.mjs` (regens `ship.js`); no re-route needed.
- *Reroute a guide:* edit the `SPECS` table in `route-waypoints.mjs` → run `route-waypoints.mjs`.

## Preview server

The repo's `docs/` is the GitHub-Pages source and the live preview root. Serve it with:

```bash
cd docs && uv run --no-project python -m http.server 8866 --bind 0.0.0.0
```

→ `http://<host>:8866/maps.html` (deck plans), `…/profile.html` (side elevation),
`…/index.html` (hub; Warden mode unlocks the maps).

> Note: the `cairn-review/` directory is **scratch** (old exploratory renders + the harness
> output under `cairn-review/decks/`). It is NOT the site and is not committed. Don't serve it
> or treat its older PNGs as current.
